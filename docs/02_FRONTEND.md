# 6. Личный кабинет

После авторизации пользователю доступны три основных раздела:

```text
Профиль
Мои задачи
Расписание
```

---

---

# 7. Профиль

Профиль содержит:

### Шапка

* имя пользователя;
* логин.

### Основная информация

* email;
* дата регистрации;
* дата/время последней завершённой генерации расписания.

---

---

# 8. Мои задачи

Раздел содержит список задач пользователя.

Для каждой задачи отображается отдельный блок/карточка.

Пользователь может:

* создать задачу;
* изменить задачу;
* удалить задачу;
* просматривать параметры задачи.

## 8.1. Параметры задачи

Минимальный набор:

* название;
* длительность выполнения;
* дата/время последнего фактического выполнения;
* периодичность;
* правило допустимого переноса;
* допустимое время выполнения.

## Дополнительные UI-решения

### Landing

- светлая, минималистичная концепция;
- вверху справа `Войти`;
- отдельные `Демо` и `Начать` не нужны;
- пример расписания состоит из 7 блоков Пн–Вс;
- внизу форма обратной связи.

### Навигация

После входа:

```text
Мои задачи | Расписание | Профиль | Выйти
```

### Tasks

Предусмотреть:

```text
Поиск задач
+ Добавить задачу
```

Карточки могут содержать примерные задачи `Отчёт`, `Бэкапы`, `Проверка почты`.

### Schedule

- weekly view — 7 дней и checkbox `Рабочий день`;
- monthly view — календарь выбранного месяца;
- массовая установка параметров для рабочих дней;
- точечное изменение отдельных дат;
- если график одинаков каждую неделю — достаточно week setup;
- если весь месяц необычный — custom calendar;
- если обычный, но с исключениями — week + changed dates.


### Logo

По текущей UI-концепции нужен:

- SVG;
- чёрный/серый;
- минималистичный;
- квадратная иконка;
- без текста;
- не обычная иконка календаря;
- оригинальная абстрактная идея, связанная с планированием/повторяемостью.

### Login / Registration

Auth-flow должен включать:

- вход;
- регистрацию;
- logout;
- восстановление пароля после утверждения auth-схемы.

Ранний mockup использовал тестовые значения вроде `Alex Johnson`, `@alex_schedule`, `alex@example.com`; это только demo data и не является фиксированными данными продукта.
