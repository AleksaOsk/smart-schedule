# 9. Периодичность задач

На текущем этапе поддерживаются следующие варианты:

```java
EVERY_DAY(
    "everyDay",
    "Каждый день"
),

EVERY_WEEK(
    "everyWeek",
    "Каждую неделю"
),

EVERY_TWO_WEEKS(
    "everyTwoWeeks",
    "Каждые две недели"
),

EVERY_THREE_WEEKS(
    "everyThreeWeeks",
    "Каждые три недели"
),

EVERY_MONTH(
    "everyMonth",
    "Каждый месяц"
),

EVERY_TWO_MONTHS(
    "everyTwoMonths",
    "Каждые два месяца"
),

EVERY_THREE_MONTHS(
    "everyThreeMonths",
    "Каждые три месяца"
),

EVERY_FOUR_MONTHS(
    "everyFourMonths",
    "Каждые четыре месяца"
),

EVERY_FIVE_MONTHS(
    "everyFiveMonths",
    "Каждые пять месяцев"
),

EVERY_SIX_MONTHS(
    "everySixMonths",
    "Каждые шесть месяцев"
),

EVERY_YEAR(
    "everyYear",
    "Каждый год"
);
```

Периодичность определяет интервал между фактическими выполнениями задачи.

Следующая плановая дата рассчитывается от даты последнего выполнения:

```text
следующая дата =
дата последнего выполнения + периодичность
```

Для периодичностей в месяцах и годах используются стандартные операции работы с датами Java (`plusMonths`, `plusYears` и соответствующие операции для других периодов).

# 10. Обработка пропущенных выполнений

Пропущенное выполнение задачи не считается ошибкой системы и не требует отдельного подтверждения пользователя.

Если дата последнего выполнения находится значительно раньше периода, на который создаётся расписание, система последовательно прибавляет периодичность, пока не получит актуальную дату выполнения.

Пример:

```text
Последнее выполнение:
01.08

Периодичность:
каждый месяц

Генерируем расписание:
октябрь
```

Система рассчитывает:

```text
01.08 + 1 месяц = 01.09
01.09 + 1 месяц = 01.10
```

Задача попадает в расписание на 01.10.

Если очередное рассчитанное выполнение уже находится за пределами месяца, для которого строится расписание, задача в этот месяц не добавляется.

Например:

```text
Последняя дата:
31.08

Периодичность:
каждый месяц

Генерируем сентябрь
```

Расчёт:

```text
31.08 + 1 месяц
```

Если после расчёта дата выходит за последний день целевого месяца, задача пропускается для этого месяца.

# 11. Подтверждение предыдущих выполнений

Перед генерацией система должна предоставить пользователю возможность подтвердить фактические даты выполнения задач.

Причина:

> Дата, сохранённая как последнее выполнение задачи, используется для расчёта следующего выполнения.

Пользователю показываются задачи, которые должны были быть выполнены согласно предыдущему расписанию.

Пользователь может:

* подтвердить, что задача была выполнена в указанную дату;
* указать новую фактическую дату выполнения;
* оставить сохранённую дату без изменений, если точная дата для него непринципиальна.

После подтверждения эти данные используются текущей генерацией.

# 12. Создание задачи в середине периода

Поведение задачи, созданной пользователем после начала её потенциального периода выполнения, требует отдельного уточнения.

Например:

```text
Сегодня 15 октября.

Пользователь создаёт задачу
с периодичностью "каждый месяц".
```

### OPEN QUESTION

Необходимо определить, какую дату считать первым выполнением новой задачи:

* дату создания;
* дату, введённую пользователем как последнее выполнение;
* ближайшую подходящую дату;
* другой вариант.

## Дополнительные зафиксированные правила

- Пропущенное выполнение остаётся на ответственности пользователя.
- Система не создаёт backfill для каждого пропущенного экземпляра.
- Перед генерацией пользователь может подтвердить/исправить сохранённую дату последнего фактического выполнения.
- Изменение даты влияет на будущую генерацию, но не переписывает уже созданное расписание.
- Изменение исходных Task settings не должно автоматически менять существующий `GeneratedSchedule`.

## OPEN QUESTIONS

- Первый execution date новой задачи.
- Нужен ли отдельный `firstExecutionDate`.
- Можно ли создать задачу без `lastExecutionDate`.
- Можно ли задать `lastExecutionDate` в будущем.
- Нужны ли `ACTIVE/PAUSED`.
- Можно ли менять Task во время `WAITING_FOR_USER`.

## IDEAS

- `ACTIVE/PAUSED` вместо обязательного удаления.
- Отдельный first execution date, если anchor через last execution начнёт мешать UX.
- Архив задач в будущем, если появится история.
