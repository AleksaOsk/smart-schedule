# 18. Рабочее расписание пользователя

Пользователь должен указать рабочие и выходные дни.

Поддерживаются два режима.

---

## 18.1. Стандартное расписание

Используется, если график пользователя повторяется каждую неделю.

Пример:

```text
Понедельник    рабочий
Вторник        рабочий
Среда          рабочий
Четверг        рабочий
Пятница        рабочий
Суббота        выходной
Воскресенье    выходной
```

Для стандартного расписания пользователь задаёт продолжительность рабочего дня.

При необходимости пользователь также указывает ночной рабочий интервал.

---

## 18.2. Кастомное месячное расписание

Используется, если рабочие дни меняются от недели к неделе.

Пользователь задаёт расписание конкретного месяца.

Пример:

```text
01.10 — 09:00–18:00
02.10 — 09:00–18:00
03.10 — выходной
04.10 — выходной
05.10 — 10:00–19:00
...
```

При выборе месяца календарь должен автоматически отображать соответствующие даты и дни недели.

В кастомном режиме пользователь может задавать конкретные рабочие интервалы для отдельных дат.

---

---

# 19. Массовое назначение рабочего времени

Чтобы пользователю не приходилось вводить одинаковое время для каждого рабочего дня вручную, необходимо предусмотреть возможность:

```text
Установить рабочее время
для всех рабочих дней
```

Например:

```text
Все рабочие дни → 09:00–18:00
```

После этого отдельные даты могут быть изменены вручную.

---

# 20. Автоматический режим рабочего времени

SmartSchedule должен поддерживать режим, в котором пользователю не требуется заранее указывать точное начало и конец рабочего дня.

В этом режиме системе в первую очередь необходимо знать:

* максимальную продолжительность рабочего дня;
* рабочие/выходные дни;
* наличие дневного рабочего времени;
* наличие ночных смен;
* продолжительность перерыва/отдыха.

Точное начало рабочего дня в автоматическом режиме не является обязательным ограничением.

Система должна самостоятельно определить размещение задач в пределах доступной продолжительности рабочего времени.

Если пользователь использует ночные смены, система учитывает указанный пользователем ночной интервал.

# 21. Перерывы

Пользователь должен иметь возможность указать продолжительность рабочего перерыва / отдыха.

Перерыв учитывается при расчёте доступного времени для задач.

### FIXED CLARIFICATION

В автоматическом режиме точка/расположение перерыва не моделируется.
`restDuration` просто вычитается из доступного времени:

```text
доступное рабочее время = максимальная длительность рабочего дня - отдых
```

Поддержка нескольких/фиксированных интервалов может появиться позже, но не является обязательной для MVP.

---

## Дополнительные уточнения

В automatic mode пользователь не обязан указывать точное начало дня. Основные параметры — максимальная длительность рабочего дня, рабочие/выходные дни, DAY/NIGHT и отдых.

Перерыв не моделируется как отдельный временной блок: его длительность вычитается из доступной ёмкости.

### DAY_AND_NIGHT

Означает `time-of-day independent`: задача может выполняться в подходящем доступном рабочем времени. Это не требование одновременно использовать DAY и NIGHT.
